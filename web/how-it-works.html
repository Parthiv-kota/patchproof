Mechanism

Three hashes and a command.

A receipt is small on purpose. Everything it claims comes from comparing the same list of files at three moments: before the check, right after it, and whenever you look again.

The lifecycle

What happens during patchproof run

Expand the watch list

Explicit files, folders and globs are resolved once, inside the project root. Symbolic links, absolute paths and parent traversal are rejected; VCS metadata, virtual environments, caches and dependency folders are skipped.

Fingerprint the inputs

Each watched file is read once and hashed with SHA-256. Only digests are kept — never file contents, never the command's output.

Run the command you named

Launched directly, without a shell, inside the project root, with a timeout. Stdout and stderr stay in your terminal. The exit code and duration go into the receipt.

Fingerprint again

If the before and after digests differ, the check modified its own inputs — a distinct state from an ordinary pass, and one that is easy to miss without a second sample.

Write a new file, never overwrite

The receipt is written only if the target path does not already exist. Existing receipts and reports are never replaced, so a passing record cannot be quietly rewritten by a later run.

Seven states

What patchproof status can say

Each state names the next action, not just the verdict. If several problems apply, a changed-during-check or an unavailable snapshot takes precedence over later freshness.

StateMeaningNext step
current_passedExit zero; before, after and current watched bytes match.Ask whether the command and the watched scope are sufficient.
current_failedThe command exited non-zero; the bytes still match that run.Investigate the failure — the receipt is honest about it.
changed_since_checkA watched file changed or is missing since the recorded run.Run the check again and write a new receipt.
changed_during_checkBefore and after fingerprints differ.Inspect the mutation and rerun on stable inputs.
current_timed_outThe command exceeded its time limit.Investigate before choosing a longer limit.
current_errorThe command could not be launched.Check the executable and environment.
snapshot_unavailableNo usable after-check snapshot exists.Resolve inaccessible inputs and rerun.

Exit codes: 0 for current_passed, 1 for any other state, 2 for an input or tool error. The child command's own exit code is stored in the receipt, not passed through.

Data boundaries

What is stored, and what is not.

Stored in the receipt

  • Schema version, scope and state.
  • The command's executable and arguments.
  • Exit code, start time, duration.
  • SHA-256 digests before and after the run.
  • A fixed, plain-language limits string.

Never stored

  • File contents or diffs.
  • The command's stdout or stderr.
  • Environment variables or credentials.
  • Anything about other files in the project.
  • Any telemetry or usage event.

Arguments and filenames are still data. They are stored verbatim and can be sensitive. Review a receipt before sharing it, and keep secrets on stdin or in the environment rather than in the command line.

In the browser

The viewer never runs your code.

The static viewer loads a receipt JSON, asks for the project folder, and hashes only the watched paths in that folder using the browser's own crypto API.

Locked down

A content-security policy forbids external scripts, uploads and frames. There is no network client in the page at all.

Validated input

Imported JSON is treated as data: shape, digests, path containment and size are checked before anything is rendered.

Memory only

Receipts and comparisons live in memory and disappear on reload. Export produces a Markdown summary you can review before sharing.

With an agent host

Skills guide the model. They are not an enforcement layer.

The three bundled Codex skills describe how to review a change, make a focused fix, and prepare a handoff. They operate inside the host's own permissions, approvals and usage limits, and they explicitly do not authorise publishing, messaging, deploying or installing dependencies.

Codex skills       → review, focused fixes, factual handoffs
snapshot.py        → read-only inventory of local Git changes
receipt.py run     → watched hashes + chosen command + outcome
receipt.py status  → compare current files with the recorded inputs
Browser viewer     → open, compare and explain receipts locally
